## Что это

mcp-airlock — прокси, который ставится между ИИ-агентом и MCP-сервером, когда сервер умеет делать
вещи, которые агенту не стоит делать самостоятельно. Он работает по редакции протокола 2026-07-28
(без сессий и `initialize`, один POST на запрос) и добавляет то, что протокол оставляет на ваше
усмотрение: кто и что может вызывать, dry run по умолчанию, человек в контуре для опасных вызовов,
журнал аудита и трассировка.

Прокси намеренно маленький: без UI, без языка политик сложнее плоского YAML, без собственного
MCP SDK. Это одно приложение на Starlette и несколько вспомогательных модулей.

## Главное

* **Кто вызывает.** Принципал берётся из JWT (HS256 или JWKS) или из заголовка
  `X-Airlock-Principal` за вашим шлюзом, но не из тела запроса. Нет принципала — нет вызова.
* **Allowlist и уровни риска.** Тул, которого нет в политике, отклоняется. У каждого тула уровень
  `L0` (чтение), `L1` (всегда `dry_run: true`), `L2` (подтверждение человеком) или `L3`
  (как отправлено) на каждое окружение, так что один и тот же `delete_service` свободен в `dev` и
  под замком в `prod`.
* **Подтверждение.** Вызов `L2` сначала идёт как dry run, агент получает `input_required` с
  описанием последствий, а выполняется вызов только после «да» и ровно один раз. Подтвердить можно
  по ссылке из Slack или Telegram (по умолчанию, если задан вебхук) или ответом самого клиента.
* **Ограничения.** Условия `where` по значениям аргументов (regex на RE2), blast radius (сколько
  объектов за вызов и за час или сутки на принципала), обрезка слишком длинного вывода тула,
  лимиты на тело запроса и на ответ апстрима.
* **Защита от подмены.** Пины описаний тулов (`airlock-policy pin`), пометка подозрительных фраз
  (prompt injection) в ответах.
* **Аудит.** Две записи на вызов (до обращения к апстриму и после) в JSONL-файл с хеш-цепочкой,
  ротацией и `airlock-audit verify`; по желанию зеркало в Postgres. Секреты в аргументах
  скрываются. В `_meta` каждого результата стоят вердикт и правило.
* **Эксплуатация.** Трассировка OpenTelemetry (файл и OTLP), `/healthz` и `/readyz`, общее
  состояние в Postgres для нескольких реплик, Helm-чарт, готовые политики для серверов GitHub,
  Grafana, Kubernetes и Postgres в `examples/policies/`.

Отказы приходят как результаты тула с `isError: true`, а не как ошибки протокола, чтобы модель
видела причину и могла поступить иначе.

## Быстрый старт

```
uvx mcp-airlock --policy policy.yaml --upstream http://127.0.0.1:8080/mcp --env prod
```

То же в контейнере:

```
docker run --rm -p 9000:9000 -v $PWD/policy.yaml:/data/policy.yaml \
  --add-host=host.docker.internal:host-gateway \
  ghcr.io/shalimov04/mcp-airlock:0.3 --policy policy.yaml --upstream http://host.docker.internal:8080/mcp --env prod
```

Минимальная политика:

```yaml
version: 1
environment: prod
tools:
  get_service:
    tiers: { dev: L0, prod: L0 }
  delete_service:
    description: безвозвратно удалить сервис
    tiers: { dev: L2, prod: L2 }
```

Проверить политику без сети: `uvx --from mcp-airlock airlock-policy lint policy.yaml`.

Дополнительные возможности ставятся как extras: `postgres` (общее состояние и аудит в Postgres),
`otlp` (экспорт спанов), `regex` (правила `where` с `regex`; без него такая политика не
загрузится). Образ контейнера включает все три.

Как подключить Claude Code и Cursor и какие клиенты умеют `input_required`:
[docs/clients.md](docs/clients.md). Всё остальное — в [README.md](README.md).
